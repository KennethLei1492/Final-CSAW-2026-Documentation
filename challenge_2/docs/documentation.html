2. The accelerator & cipher

Identified as Ascon-AEAD128 (NIST SP 800-232): 320-bit sponge state (x0..x4), 128-bit key/nonce/tag, IV 0x00001000808c0001, 12-round init/final (pa) and 8-round data (pb) permutations, round constants 0xf0..0x4b, rotation pairs x0(19,28) x1(61,39) x2(1,6) x3(10,17) x4(7,41), tag = x3‖x4. The reconstruction work/sim/ascon_ref.py was structurally matched to the official reference and passes 200 randomized encrypt/decrypt roundtrips; it is the oracle for the Verilog DUT.

Key provisioning path

At power-up an I2C master reads a 64-byte image from EEPROM 0x50 and validates it:

0x00 magic(4)="ASCN"  0x04 ver(1)=0x01  0x05 rsv(9)=0  0x0E crc16(2,BE)
0x10 key(16)          0x20 nonce(16)    0x30 secret(16)

Validation = magic + version + CRC-16/CCITT-FALSE over bytes 0x10..0x3F. Implemented in rtl/i2c_eeprom_loader.v, verified by tb/tb_loader.v (sample image CRC 0xB9A1).

4. The three Trojans

The clean RTL has no Trojan logic and no ifdefs; each Trojan is grafted in by an insertion pass (tools/insert_trojan.py) that splices trigger + payload at the //@TJ-* anchors, emitting work/trojans/crypto_top_{A,B,C}.v. Every inserted Trojan keeps the full self-test passing, fires only on a rare trigger never present in normal/self-test traffic, and still fits the UP5K (§7).

Trojan A — full key-material leak → decrypt + forge trigger: host nonce

  • Trigger: host nonce = A5A5…A5 (2⁻¹²⁸) on an encrypt.
  • Payload: trjA_fire captures the FPGA-isolated r_key, r_nonce, r_secret into a shadow register served on the host-readable OUT read path at OUT[0:15]/[16:31]/[32:47] (arming clears at the next START, so only the triggering op leaks). Leaking on the read side keeps the single-write-port OUT block-RAM inferred as EBR, so the infected design still fits.
  • Demonstrated (C and I): PASS normal op does not leak; PASS under the magic nonce OUT[0:47] == key‖IV‖secret (000102…0e0f ‖ 1011…1e1f ‖ 5365…36ff); PASS a ciphertext the attacker forged offline with the leaked key for "ADMIN:grant-root" is accepted (AUTH_OK) and returns the attacker-chosen plaintext.
  • Impact credited: C:H (key/secret disclosure) and I:H (accepted forgery) — both tested.

Trojan B — auth bypass + plaintext recovery trigger: reserved CFG bit

  • Trigger: reserved CFG[7] on a decrypt. Chosen over an AD trigger because the AD mixes into the Ascon state and would corrupt the recovered plaintext; a reserved control bit leaves the datapath intact.
  • Payload: trjB_fire = cfg[7] & (op==DEC); at completion crypto_top forces AUTH_OK and clears the withhold flag, releasing the plaintext the engine already produced. A captured ciphertext replayed with its real AD and a bogus tag decrypts to the correct plaintext. The engine itself is left generic — no Trojan hook in the datapath.
  • Demonstrated: PASS forged-tag decrypt ACCEPTED; PASS correct plaintext recovered with a bogus tag; PASS control (no trigger) rejects & withholds.
  • Impact credited: C:H (plaintext recovery) and I:H (forgery acceptance) — both tested.

Trojan C — forced nonce reuse trigger: message prefix

  • Trigger: message[0:3] = C0FFEE00 on an encrypt, snooped from the host write stream (so no async read of the MSG block-RAM, which would defeat BRAM inference).
  • Payload: trjC_fire overrides the CFG-selected nonce source with a fixed constant, so repeated encryptions reuse one key+nonce.
  • Demonstrated: PASS keystream collision across two different host nonces; PASS an unknown second plaintext recovered from a known one by crib-drag (P2 = C2 ⊕ C1 ⊕ P1).
  • Impact credited: C:H (plaintext recovery). I:N — forgery / key recovery under reuse was not demonstrated, so not credited.

Distinctness: three different trigger domains (host nonce / reserved control bit / message prefix) and three different payloads (key-material leak / auth bypass + plaintext recovery / nonce reuse).

5. CVSS v3.1 — computed, source-verified, evidence-gated

Reproduce with python work/analysis/cvss.py. An earlier over-conservative pass scored 4.6/6.1/4.6 by using AV:P, S:U and withholding integrity credit. Re-examined against the FIRST CVSS v3.1 specification (and grounded by the Answer Verification model):

  • AV:L, not AV:P — the spec reserves Physical for attacks that physically touch/manipulate the component (e.g. attaching hardware to a bus). The triggers here are issued through the accelerator's existing SPI command interface via the application processor → local logical access. (AV:N/AV:A are still not claimed — no network path exists.)
  • S:C, not S:U — the IP doc states key material is "held inside the FPGA and never exposed through SPI"; each payload breaches that documented isolation boundary, delivering FPGA-protected data to the host processor (a different security authority) → Scope:Changed.
  • Integrity credited only where demonstrated — A now leaks the key and shows an accepted forgery (I:H); B shows forged-tag acceptance (I:H); C shows no forgery → stays I:N.

7. Resource usage — the design fits the UP5K

An earlier draft synthesized to ~39.8k LUT4 / ~14k FF — impossible on a 5280-LUT / ~5280-FF part. Cause: the AD/MSG/OUT buffers were flat register files read with a variable-indexed wide combinational mux, which cannot infer block RAM. The recovered production bitstream shows the right answer (4577 LUT / 7 BRAM): keep data in EBR.

Fix (now in rtl/crypto_top.v): AD/MSG are byte-wide EBR fetched byte-serially over a rd_req/rd_rdy handshake; OUT is a 128-bit-wide EBR written a whole block at a time and read a byte at a time (sub-word reads are EBR-safe; sub-word writes are not). Core crypto_top drops to ~3.7k LUT4 + 10 EBR. The full board design, placed & routed by nextpnr --up5k --package sg48 --freq 10:

All four place, route, and pack to a real .bin at a utilization in line with the recovered design's ~87% — a valid, loadable number. The Trojan footprint is small (trigger comparator + mux, plus a small shadow register for A) — ~9–59 extra LCs, EBR unchanged at 10/30.

Toolchain note: synth_ice40's default abc9 asserts in the experimental write_xaiger2 backend on this build (a tool bug, not our RTL), so LUTs are mapped with stable classic abc -lut 4 via a split flow (-run :map_luts; ice40_wrapcarry -unwrap; abc -lut 4; … -run map_cells:). That gives the real optimized counts above; -noabc would "work" but its unoptimized ~5× figures are meaningless and would not fit.
